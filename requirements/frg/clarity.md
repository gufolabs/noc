# FRG Requirement Clarity

## Scope

Readability and usability of requirement documents.

## Requirements

Requirement documents **SHOULD** be concise and focused.

A requirement document **SHOULD** contain enough context to be understood independently.

A requirement document **SHOULD NOT** include implementation details unless those details are required to define the requirement.

Requirements **SHOULD** describe desired outcomes and constraints rather than specific solutions.

## Why?

Clear requirements are easier to understand, validate and consume by developers, users and automated tools.
