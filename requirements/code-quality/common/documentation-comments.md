# Code Comments

## Scope

All source code.

## Requirements

Source code **SHOULD** contain comments when they provide additional information that cannot be easily understood from the code itself.

Comments **SHOULD NOT** duplicate the behavior already expressed by the source code.

Comments **SHOULD** explain:

- non-obvious design decisions;
- important constraints;
- assumptions;
- workarounds;
- compatibility considerations.

## Why?

Good comments preserve important knowledge that cannot be derived from the source code alone.

Avoiding unnecessary comments keeps the code readable and prevents documentation from becoming outdated.
