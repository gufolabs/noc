# NOC Requirements

## Scope

These requirements apply to all activities, assets and artifacts related to the NOC project.

The scope includes:

- all source code and software components developed as part of the NOC project
- all technical decisions, architecture and engineering practices
- all activities performed by the NOC development team
- all public communication and community activities made on behalf of the NOC project
- all documentation, educational materials and publications
- all marketing, branding and promotional materials related to NOC
- all distributions, releases and delivered products published under the NOC name

Any activity, product, artifact or communication presented as part of the NOC project is subject to these requirements.

## Vision

NOC aims to become the world's leading open-source network management and operations platform.

NOC should set the highest standards in the field of network operations by combining:

- exceptional user experience;
- powerful automation capabilities;
- operational simplicity;
- high performance and efficient resource utilization;
- scalability for networks of any size;
- reliability suitable for mission-critical environments;
- openness and extensibility expected from modern
  open-source software.

NOC should enable network operators to manage complex infrastructure with minimal manual effort and move closer to zero-operation networking.

NOC should be a platform that users love to operate, developers enjoy extending, and organizations trust for their critical infrastructure.

## Requirements

### Product

NOC **MUST** provide an open-source network management and operations platform.

NOC **MUST** provide functionality required for effective network monitoring, management and automation.

Functional requirements **MUST** be defined and maintained as a structured part of the project requirements graph.

### Open Source

NOC **MUST** remain an open-source project.

The project **MUST** provide transparent processes for development, contribution and collaboration.

### Quality

NOC **MUST** maintain high standards of software quality.

The project **MUST** produce software that is:

- maintainable;
- understandable;
- reliable;
- secure;
- testable;
- extensible.

Code and architecture **SHOULD** be designed to provide a pleasant experience for developers and contributors.

### Documentation

NOC **MUST** provide clear and accessible documentation.

Documentation **SHOULD** allow users, operators, developers and contributors to understand the system without relying on undocumented knowledge.

### Development Process

NOC **MUST** maintain predictable and transparent development processes.

Engineering decisions **SHOULD** be documented and traceable.

The project **SHOULD** provide an environment where both human contributors and AI-assisted tools can effectively understand and improve the system.

## Why?

NOC is designed as a long-lived open-source project.

Clear requirements provide a shared understanding of project goals, guide engineering decisions and allow contributors, users and automated tools to make consistent decisions.
